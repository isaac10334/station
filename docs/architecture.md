# Current architecture

## Local app

`server.ts` is a single Bun server bound to localhost. Bun serves `index.html` as a fullstack HTML route and bundles the TypeScript frontend in development. `bun run build` produces one standalone `dist/index.html`; Component builds require the Bun server. Workspace source remains in browser storage. The server accepts one source project at `/api/component/build` and stores verified Component bytes under `.artifacts/` by SHA-256 for download.

`src/main.tsx` mounts `src/workspace-app.tsx`. The app has a docked navigation panel, shared toolbar, and controlled `DockHost`. `src/docking/core.ts` owns a versioned grid/split/stack layout, typed host policy, migration, and atomic commands. `src/docking/react.tsx` renders the main, dashboard, sidebar, and bottom surfaces with one dnd-kit drag coordinator; drag state and dialogs are transient. The store in `src/model.ts` persists layout, active tabs, sizes, and browser view per workspace. Widget type is separate from instance ID, so the same built-in widget may be placed more than once. `src/unit-browser.tsx` presents a sidebar list or a larger grid/list and provides a Stealth context menu. `src/component-view.tsx` renders a Component inside a focusable dock panel. `src/web-content-view.tsx` edits local HTML/CSS/JS and runs it in a sandboxed iframe; authored web units may also have dashboard widget instances. `src/dashboard.tsx` renders the dashboard grid and per-widget controls. `src/onboarding.tsx` provides local guest and demo entry only. Tailwind v4 and locally imported shadcn/Stealth components live in `src/components`, with shared helpers in `src/lib` and styles in `src/styles.css` and `src/tailwind.css`. `components/greeting` remains the Rust/WIT project. `src/composition.ts` connects the store to browser `localStorage` and registers the existing Component runner with the linked `@loop-kit/capabilities` and `@loop-kit/host` packages. It acquires a runner for each run and revokes its scope afterward. Data uses the `unit-workspace.v4` key and migrates older flat layouts. Unit source and panel placement belong to a workspace; Component grants and artifacts are specific to Component units. Appearance and AI provider preferences belong to the app. AI settings are UI state, not an active service integration.

Stealth neutral tokens in `src/styles/stealth.css` drive light and dark themes; `src/tailwind.css` maps them to shadcn tokens. Fonttrio Technical supplies IBM Plex Sans for headings and body text and IBM Plex Mono for code. `bun run styles` creates `src/generated.css` and copies its font assets before the standalone HTML build. Dashboard widgets, including an optional GameKit Snake widget, are built-in React UI, not Component plugins. Eligible built-in widgets can float with stable panel IDs and return to a dock. Broader tiling presets and plugin surfaces remain [exploratory work](explorations/surface-system.md).

Docking policy is host-owned typed configuration. Main permits four leaf stacks; sidebar and bottom permit one each; dashboard remains a widget grid. Navigation is a singleton panel in the sidebar stack. The shared main toolbar sits below its real tab rail, while split leaves own local tab rails. Layout and floating placement persist per workspace; surface visibility and bounded undo/redo history are session-only. The developer inspector is an overlay outside the dock document. See [docking system](../src/docking/README.md).

The dashboard's weather, clock, stack, capability inspector, and optional Snake widgets are built-in React UI, not Component plugins. Weather requests browser location only when pressed and then reads Open-Meteo; it does not infer a city or grant location to a Component. Each widget panel persists color, size, and stack mode in the v3 dock document. Size presets cause the grid to reflow. The v2 migration replaces removed starter widgets with weather, clock, and stack once.

## Web content path

Web content units persist one authored HTML document locally. Their editor and dashboard placements use `srcDoc` iframes with `sandbox="allow-scripts"` and no `allow-same-origin`, so script runs with an opaque origin and cannot read the host DOM or storage. A CSP meta policy placed before authored markup denies external scripts, resource loads, connections, forms, objects, and child frames in the authored document; it permits inline script and style for small widgets and data images/fonts. There is no `postMessage` bridge. Preview reload is explicit during editing; dashboard widgets run the current saved source.

The Bun server rejects `/api/*` requests with a foreign or `null` Origin, rejects cross-site Fetch Metadata, and requires the exact app Origin for mutating requests. These checks protect Component build and artifact routes from opaque iframe requests. The app is still a localhost, single-user application: its API is not authenticated for remote deployment. A CSP on a `srcDoc` document does not guarantee that a navigated iframe keeps that policy, so this initial web unit must not be represented as a network-proof marketplace runtime. Marketplace content needs separate-origin serving with response headers, navigation and communication rules, backend authentication, resource limits, and review before installation.

## Component path

The unit browser keeps multi-selection as temporary view state. Toolbar, context menu, and Delete key actions confirm before one store update removes the selected units and their dock panels. Each unit has an instance ID, including units migrated from older storage, so a build finishing after deletion cannot install onto a replacement with the same slug and source.

`components/greeting` is an editable Rust/WIT source project. Its world exports `async run(string) -> string`, imports a P3 monotonic clock, and uses a host-provided future and stream in addition to logging and a bounded text surface. `bun run build:component` builds it with pinned nightly Rust and `wit-bindgen` 0.60.0 for `wasm32-wasip2`, inspects the resulting Component with Polyengine, invokes it, and embeds only sample source into the app. The target name does not determine the Component profile: inspected async types and `wasi:*@0.3.1` imports do. Rust's standard library also contributes recorded `wasi:*@0.2.12` imports.

`src/component-runtime.ts` selects the Polyengine provider for the inspected P3 profile, verifies downloaded bytes, and transfers them to a one-shot fixed worker. The worker checks the pinned translator asset hash, translates and inspects the bytes again, rejects unsupported imports, and instantiates with run-local WIT providers and Polyengine's minimal WASI capture/empty-filesystem provider. WIT grants are checked before execution and again at each workspace host effect. The host supplies a Promise and ReadableStream for the P3 future and stream; handles stay in the worker. The worker returns bounded plain results and effects, then terminates. Abort, grant revocation, source changes, deletion, and a 30-second timeout also terminate it. Loop Kit's host acquires and revokes the runtime capability; its signal is cooperative and does not enforce guest permissions. The worker is the hard stop.

`component-build.ts` creates a nonpersistent Vercel Sandbox from the pinned 30-day snapshot in `vercel-sandbox.json` for each build. It uploads the unit's Cargo lockfile, Rust, and authored/vendored WIT, runs nightly `cargo build --release --offline --locked --target wasm32-wasip2` with network denied, inspects the actual P3 world/imports, hashes the bytes, and deletes the Sandbox. The versioned manifest records a unique build ID, canonical source and WIT hashes, byte hash/count, inspected world/imports, profile, toolchain, snapshot ID, and translator hash. Wasm bytes are content-addressed; each build gets a separate immutable manifest even when different sources compile to identical bytes. This is recorded provenance, not a cryptographic build attestation. The client fetches and verifies the exact bytes before install and again before each run. Source edits invalidate the artifact; an instance ID prevents a deleted/recreated unit from receiving a prior build.

This locally authored Component path is not a marketplace security boundary. Wasm isolates guest memory, while the same-origin worker and import membrane limit authority. Polyengine does not claim hostile-guest confinement from provider checks alone. A separate-origin runner, tighter resource accounting, and a third-party iframe policy are required before untrusted marketplace Components are accepted. See [runtime measurements](component-runtime-profile.md).
