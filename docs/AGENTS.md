# Documentation work

Read [README.md](README.md) and the affected topic owner before editing.
Keep one owner for each contract, decision or acceptance record; link it elsewhere.
Separate implemented behavior, dated evidence and proposals.
Describe the source or target checked and keep unresolved acceptance visible.

Before merging or deleting a page, inspect inbound references and its unique facts.
Preserve compatibility, authority, lifecycle and failure invariants in their owner.
Move useful acceptance details before removing duplicates, then fix links/anchors.
Do not promote old test counts or screenshots into evidence for newer source.

Write direct prose with concrete subjects; use stop-slop when it improves the edit.
Record consequential unanswered design questions in [Loop QUESTIONS.md](C:/src/ilt/loop/QUESTIONS.md).
Name the tradeoff instead of inventing an answer or adding an approval ritual.
Use the [upstream agent workflow](C:/src/ilt/loop/docs/reference/agent-workflow.md)
for verified TickTick/task coordination; keep those instructions out of topic docs.
