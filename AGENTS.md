# Station agent notes

Station is intended to become a self-extending workspace and a full Loop Kit host. People should be able to create and manage units, then use them to extend the workspace from within the app. WebAssembly Components are one extension path, alongside other possible unit types. Favor dynamic creation and execution workflows. Clearly distinguish working behavior from proposals.

- **UI:** Read [DESIGN.md](DESIGN.md) before UI work and use its relevant design skills. Keep built-in React UI distinct from future capability-provided surfaces. Use semantic color and state tokens; preserve keyboard access, visible focus, and shortcuts that yield to inputs, games, and editors.
- **Code boundaries:** Keep rendering and temporary view state separate from workspace and app state and from effectful services such as storage, grants, builds, and execution. Use descriptive, responsibility-based module names. Treat `model.ts` and `composition.ts` as current code, not prescribed homes for every new feature.
- **Loop Kit:** This repo links `@loop-kit/capabilities` and `@loop-kit/host` from `C:/src/ilt/loop`. Before adding overlapping generic capability or provider behavior, inspect their exported types and TSDoc, then their README or source as needed. The JS host manages lifecycle; it does not itself enforce guest permissions.
- **Source documentation:** Document public and reusable contracts, lifecycle boundaries, and non-obvious invariants beside the code with TSDoc. Include a small example when another module or package consumer needs one; do not require examples for routine private UI pieces or write comments that repeat code.
- **Runtime claims:** Source edits must invalidate their built artifact. Verify real source, bytes, grants, and invocation before reporting a build or run as successful; mocked or stale output is not proof.
- **Verification:** After code changes, run `bun run typecheck` and `bun run build`. For Rust, WIT, generated bindings, or Component runtime changes, also run `bun run build:component`. Verify affected UI and runtime behavior in a browser: built-in Browser, then Edge, then Chrome. Use Computer Use only when needed; report if all browser options fail.
- **Docs:** Consult [docs/architecture.md](docs/architecture.md) for relevant current boundaries, [docs/decisions.md](docs/decisions.md) for durable choices, and [src/docking/README.md](src/docking/README.md) for docking work. Update a document when the change makes it materially stale. Label exploratory material as such.
