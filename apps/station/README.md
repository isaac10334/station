# Station application

One private application workspace owns the browser UI, development API, and
Electrobun desktop entrypoint. Run the usual `bun run dev`, `typecheck`, `test`,
`build`, and `desktop:build` commands from the repository root.

| Directory | Responsibility |
| --- | --- |
| `src/core` | Asset/desk state, migrations, docking policy/reducer, validated source/package/theme data. No React, providers, or application bootstrap. |
| `src/contracts` | Private host-side AI, Component invocation, and worker transport contracts. |
| `src/providers` | Loop Kit provider implementations, AI conversation execution, Component inspection and execution. |
| `src/services` | Editor sessions, builds/language workers, grants, guest RPC, and package orchestration. Effectful package services take explicit composition dependencies. |
| `src/ui` | React presentation, components, docking geometry/interaction, styles, icons and view state. |
| `src/composition.ts` | Application wiring: storage, providers, scopes, service factories, and lifecycle ownership. |
| `server` | App-origin API, cloud Component builds, and development server. |
| `desktop` | Native entrypoint, persistent installed resources, and updates. |
| `scripts` | App-owned build/resource/desktop preparation. |

Public identities and serializable guest types live in `@station/capabilities`.
The independently packable `@station/sdk` owns the guest connection. Host providers
are not shipped as part of either public package.

Workspace declarations and one lockfile live at the repository root. Root
`typecheck` prepares public package artifacts and compiler resources first, so it
does not depend on a previous development/build run. On a new checkout, run
`bun run desktop:prepare` once before checking the native entrypoint, as CI does. App scripts
resolve installed dependencies through package resolution, not a particular hoisted
`node_modules` layout. The development server runs with the repository watch root.
After changing the public packages, rebuild them with `bun run build:packages`; embedded
guest compiler resources are regenerated by restarting `bun run dev`.

Development Component artifacts continue to use the legacy repository `.artifacts`
directory. Installed desktop artifacts stay in the user's existing channel data
directory. Source moves do not rename storage keys, WIT IDs, asset IDs, or placements.
